# Go 後端分層設計

目標是讓 `cmd/server/main.go` 只負責組裝依賴與啟動 HTTP Server，不放遊戲流程、Bot 決策或資料轉換邏輯。

## 目標目錄

```text
cmd/server/
└── main.go                         # 啟動入口、依賴組裝

internal/server/
├── http.go                         # route、CORS、HTTP middleware
├── game_handler.go                 # HTTP request/response 轉換
└── game_view.go                    # domain -> public JSON view

internal/application/
├── game_service.go                 # 建立、開始、送出 command 的用例
├── period_service.go               # KPI 完成後進入下一期
└── bot_service.go                  # Bot 的策略與自動行動

internal/domain/
├── game_types.go                   # Period、Card、Player、Game 狀態
├── game_setup.go                   # 建立遊戲、初始卡、KPI
├── game_experiment.go              # 選牌、打牌、棄牌、傳牌
├── game_finance.go                 # 貸款、利息、營收、現金流
├── game_learning.go                # 市場抽取、顧客、期末結算
└── game_ranking.go                 # 分數與排名

internal/catalog/
└── loader.go                       # fixture 載入與 catalog 組合
```

## 每一層的責任

### `cmd/server`

只做啟動與依賴組裝：

```go
func main() {
    repo := memory.NewGameRepository()
    service := application.NewGameService(repo, catalogLoader)
    handler := server.NewHandler(service)
    log.Fatal(http.ListenAndServe(":8080", handler))
}
```

`main` 不應該知道 `SetKPIs`、`DrawMarket`、`BeginExperiment` 或 Bot 的細節。

### `internal/server`

只處理 HTTP 邊界：

- 解析 JSON、session token、game version
- 呼叫 application service
- 將錯誤轉成 HTTP status 與 error code
- 將 application DTO 轉成 JSON

這一層不應直接操作 `domain.Game` 的欄位，也不應決定何時進入下一期。

### `internal/application`

負責一個完整用例的協調：

- 建立遊戲並載入 catalog
- 開始遊戲與補 Bot
- 接收 command 並檢查版本／冪等性
- 所有玩家 KPI 完成後呼叫 domain 開始下一期
- 呼叫 Bot service 執行電腦玩家行動

這一層可以依賴 domain，但 domain 不依賴 application 或 HTTP。

### `internal/domain`

只放遊戲規則與狀態轉移：

- 期別與 phase 合法性
- 選牌、打牌、傳牌
- 市場袋抽取與顧客結算
- 貸款、利息、營收、現金流
- KPI 計分

Domain method 應該可在沒有 HTTP server 的情況下被單元測試。

## 目前 `main.go` 的搬移對照

| 目前內容 | 目標位置 |
|---|---|
| `gameStore`、`gameRoom` | `internal/application` 的 memory repository |
| `gamesHandler`、`setupHandler`、`startHandler` | `internal/server/game_handler.go` |
| `commandHandler` | `internal/server/game_handler.go` + application command service |
| `applyCommand` | `internal/application/game_service.go` |
| `beginNextPeriod`、`allKPIsSelected` | `internal/application/period_service.go` |
| `runBots`、`setRandomBotKPIs` | `internal/application/bot_service.go` |
| `room.view` | `internal/server/game_view.go` |
| `writeJSON`、`writeCode`、`withCORS` | `internal/server/http.go` |
| `randomID`、`commandKey` | application 的 ID／idempotency utility |
| `main` | 保留在 `cmd/server/main.go` |

## 建議的拆分順序

1. 先將 `gameStore` 抽成 memory repository，保留相同介面。
2. 將 command dispatch 與 period orchestration 抽成 `GameService`。
3. 將 HTTP handler 改成只呼叫 `GameService`。
4. 將 view serialization 與 HTTP helper 移出 main package。
5. 最後依 domain responsibility 拆分目前的 `game.go`。

每一步都以既有 Go tests 與 HTTP lifecycle test 驗證，確保 API 行為不變。
